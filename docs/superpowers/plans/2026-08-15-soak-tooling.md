# SOAK Tooling — diff / aggregate / synth-fixtures

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** three small scripts that make the per-branch validation playbook (`2026-08-15-branch-validation-playbook.md`) fully executable.

**Blocks:** every branch's step 4 (diff scorecards) and step 3 in fixtures-only-testing mode.

**Effort:** one focused session, ~2-3 hours.

## Global Constraints

- **All three scripts use only stdlib + `websockets`** (already a transitive dep). No new dependencies.
- **Output is human-friendly first, machine-parseable second.** Colored output when tty, JSON output with `--json` flag.
- **Each script has a self-test** that runs on synthetic input (no real logs, no real WAVs needed to run the tests).
- **Live under `apps/api/scripts/soak/`** — the SOAK harness's home.

## File Structure

```
apps/api/scripts/soak/
  diff-scorecards.py          Compare 2 report dirs, flag regressions
  aggregate-soak.py           Roll up N scorecards to per-scenario summary
  synth-fixtures.py           ElevenLabs → 10 scenario WAVs
  README.md                   How to run each
apps/api/tests/
  test_soak_diff.py
  test_soak_aggregate.py
  # No test for synth-fixtures — it's an API-call script, tested manually.
```

- Test: `apps/api/tests/test_soak_diff.py`

**Contract:**
```
diff-scorecards.py --baseline BASELINE_DIR --candidate CANDIDATE_DIR [--json]

Reads all *.json in each dir (verify-call.sh output).  Groups by
scenario_id (extracted from filename convention baseline-<date>-<n>-<sid>.json
OR falls back to hashing the callsid).

Output per scenario:
  scenario_1: baseline 3 pass, candidate 3 pass    → no change
  scenario_2: baseline 3 pass, candidate 2 pass    → REGRESSION (1 lost)

Exit 0 iff no scenario regressed.  Exit 1 on any regression.
```

## Task 2: aggregate-soak.py

**Files:**
- Create: `apps/api/scripts/soak/aggregate-soak.py`
- Test: `apps/api/tests/test_soak_aggregate.py`

**Contract:**
```
aggregate-soak.py DIR [--json] [--min-per-scenario N]

Reads all *.json in DIR.  Rolls up:
  scenario_1: 3 calls, 3 pass, 0 miss, 0 fail    ✅ ≥2 required
  scenario_2: 5 calls, 3 pass, 1 miss, 1 fail    ⚠️  fail seen
  scenario_5: 1 call,  1 pass                    ❌ under min_per_scenario=2

Overall:
  20 calls scored
  6 of 8 scenarios have ≥2 passes
  2 fail markers seen (scenario_2, scenario_7)

Exit 0 iff every scenario has ≥ --min-per-scenario passes AND zero fail markers.
```

- [ ] **2.** Run test → FAIL

## Task 3: synth-fixtures.py

**Files:**
- Create: `apps/api/scripts/soak/synth-fixtures.py`
- Create: `apps/api/data/soak_fixtures/README.md` (auto-generated by first run)

**Contract:**
```
synth-fixtures.py [--out-dir DIR] [--voice VOICE_ID]

Reads scenario text from docs/soak/scenarios.md (the caller-side text).
For each scenario 1-8, synthesizes caller-side speech via ElevenLabs.
Outputs µ-law 8kHz WAV to soak_fixtures/s{N}-{slug}.wav
(matching the names in docs/soak/fixtures-README.md).

Requires ELEVENLABS_API_KEY.  Uses the cheapest Flash v2.5 model.
```

**Steps:**
- [ ] **1.** Parse scenarios.md — extract "Caller says" text per scenario
- [ ] **2.** ElevenLabs Flash v2.5 HTTP call per text
- [ ] **3.** Convert response (PCM 16-bit) → µ-law 8kHz
- [ ] **4.** Write to `apps/api/data/soak_fixtures/s{N}-{slug}.wav`
- [ ] **5.** Verify output plays via `afplay` OR loads via `wave.open`
- [ ] **6.** Commit script (WAVs stay gitignored per fixtures-README convention)

**Note:** the synthesized voices are NOT the same as real callers — the whole point of Phase 0 is real-call validation.  This tool enables faster regression testing between real-call soaks (e.g. "did commit X break scenario 1?" — replay the fixture, don't re-dial).
