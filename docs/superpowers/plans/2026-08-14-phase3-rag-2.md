# PHASE 3 — RAG 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** business Q&A becomes deterministic, cited, and freshness-aware. Kill the "LLM decides to call lookup_answer" pattern.

**Architecture:** structured facts as first-class typed objects (not free text), FTS + vector hybrid retrieval, local reranker on the 2×3090 rig, direct Knowledge-lane routing (no LLM dispatch), contradiction detection + freshness gate.

**Tech Stack:** Python + SQLite (KB) + local vLLM reranker (bge-reranker-v2-m3) accessed via HTTP from laptop + existing packages/rag/ machinery.

## Global Constraints

- **Blocks on PHASE2 sub-phase 2c.** Kernel must own Knowledge-lane routing before we optimize its retrieval.
- **2×3090 rig hosts the reranker.** If the rig is unreachable, reranker path falls back to no-rerank (top-k from FTS+vector union) and logs a WARN — not an error.
- **`shape_for_voice()` MUST be dead before this phase starts.** Doc #56 line 44 + PHASE2 2b Task 3. Verify with `git grep shape_for_voice` returning zero hits.
- **Every spoken fact carries a citation.** KB entry ID + confidence in the log. Confidence < 0.7 → don't speak, escalate or clarify.
- **Freshness matters.** Answers stale (>N days) → prefix with "as of <date>" OR trigger a KB sync. Never silently serve stale.
- **Speculative retrieval on partials is READ ONLY.** Never a write, never a state mutation. Cancellation semantics MUST leave zero orphaned retrievals.

## Task 4: Knowledge-lane router (kills LLM tool-dispatch for questions)

- Modify: `packages/dialogue/knowledge_lane.py` (from PHASE2 2b) to consume the router
- Test: `apps/api/tests/test_knowledge_lane_router.py`

**Interfaces:**
- Input: caller turn text + intent-classifier tag ("question")
- Output: `RoutedRetrieval` with candidate KB entries pre-fetched, before any LLM call

**Sequence:**
1. Intent-classifier tags the turn "question"
2. Router runs FTS + vector over KB
3. Reranker refines
4. Top-3 candidates → structured-facts extractor
5. If any fact has confidence ≥ 0.7 → realizer renders it directly, no LLM
6. If not → fall back to LLM synthesis over the candidates

## Task 6: Speculative retrieval on partials

**Files:**
- Create: `packages/rag/speculative_prefetch.py`
- Modify: `packages/runtime/streaming_stt_bridge.py` — emit partials to prefetch
- Test: `apps/api/tests/test_speculative_prefetch.py`

**Design:**
- On each STT partial of length ≥ 3 words: kick off retrieval if this partial LOOKS like a question (intent-classifier or simple regex)
- Retrieval is background; result cached by `(call_id, partial_text_hash)`
- When end-of-turn fires: if the final text matches a cached partial → skip re-retrieval, use cache
- If final text diverges → drop cached (orphan cleanup must be atomic)
- NEVER a tool-call or state mutation — READ ONLY
